# x402 paywall: Cardano or Solana, paid in stablecoin

`POST /x402/route` is HAAS's pay-per-request front door for agents that don't speak Masumi. It
answers an unpaid call with HTTP 402 listing **every chain it accepts**; the client pays on one of
them, retries, and gets `202 {job_id, status_url}` once the payment has settled on chain.

| Chain | Network id | Asset (default) | Facilitator (default) |
|---|---|---|---|
| Cardano Preprod | `cardano:preprod` | USDM, `16a55b2a…ddde.0014df10745553444d` (Masumi's) | Cardano Foundation hosted, `https://x402.preprod.dev.ecosyseng.cf-deployments.org`; self-hosted `infra/x402-facilitator` as fallback |
| Solana devnet | `solana:devnet` (= `solana:EtWTRABZaYq6iMfeYKouRu166VU2xqa1`) | USDC, `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU` | `https://x402.org/facilitator` (testnets only) |
| Cardano Mainnet | `cardano:mainnet` | USDM, `c48cbb3d…47ad.0014df105553444d` | Cardano Foundation hosted, `https://x402.mainnet.dev.ecosyseng.cf-deployments.org` |
| Solana mainnet | `solana:mainnet` | USDC, `EPjFWdd5…Dt1v` | set `X402_SOLANA_FACILITATOR_URL` (x402.org is testnet only) |

Both chains use the x402 v2 `exact` scheme: the price is fixed, so `upto` (pay up to a cap,
settle the actual) is not needed. `@x402/svm` ships `upto` if per-request metering is ever wanted.

## The one-config switch

Everything is in `~/.haas/.env`. The chains on offer are one variable:

```sh
X402_NETWORK=cardano:preprod,solana:devnet   # default: one 402, client pays on either chain
X402_NETWORK=cardano:preprod                 # Cardano only
X402_NETWORK=solana:devnet                   # Solana only
```

A listed network is offered only when its receiving address is set (`X402_PAY_TO` for Cardano,
`X402_SOLANA_PAY_TO` for Solana), so setting or clearing an address also switches a chain on or
off. The server logs what it offers at startup:

```
x402 enabled: POST /x402/route costs 0.5 USDM on cardano:preprod or 0.5 USDC on solana:devnet; facilitators https://x402.preprod.dev.ecosyseng.cf-deployments.org, http://localhost:4022, https://x402.org/facilitator
```

## All settings

| Variable | Default | Meaning |
|---|---|---|
| `X402_NETWORK` | `cardano:preprod,solana:devnet` | Networks offered, comma-separated (see table above) |
| `X402_ASSET` | `auto` | `auto` = each chain's stablecoin. `USDM`, `USDC` or `ADA` keeps only chains with that asset; `ADA` prices Cardano in lovelace |
| `X402_PRICE_USD` | `0.5` | Price per routing request, in the stablecoin |
| `X402_PRICE_LOVELACE` | `2000000` | Price when `X402_ASSET=ADA` |
| `X402_PAY_TO` | unset | Cardano receiving address (`addr_test1…` on preprod) |
| `X402_FACILITATOR_URL` | hosted CF facilitator for the network | Cardano facilitator |
| `X402_FACILITATOR_FALLBACK_URL` | `http://localhost:4022` | Used when the Cardano facilitator above is unreachable; `off` disables |
| `X402_CARDANO_USDM_UNIT` | Masumi's USDM | USDM unit on Cardano, `policyId.assetNameHex` (or without the dot) |
| `X402_SOLANA_PAY_TO` | unset | Solana receiving wallet (base58). Its USDC token account must exist |
| `X402_SOLANA_FACILITATOR_URL` | `https://x402.org/facilitator` | Solana facilitator |
| `X402_CLIENT_MNEMONIC`, `BLOCKFROST_PROJECT_ID` | unset | Spike client, Cardano |
| `X402_SOLANA_CLIENT_SECRET`, `SOLANA_RPC_URL` | unset, public devnet RPC | Spike client, Solana |

**Which USDM on preprod.** Two tokens are called USDM on preprod: Masumi's
(`16a55b2a349361ff88c03788f93e1e966e5d689605d044fef722ddde` + `0014df10745553444d`, the one the
Masumi payment service and the hackathon agent guide use) and the default in `@x402/cardano`
(`e675b46e4d2242c991a8932a99db3044e80515ae14b4c4ccf6b3f4c9` + `0014df10745553444d`). HAAS defaults to
Masumi's. If your wallet holds the other one, set `X402_CARDANO_USDM_UNIT` to it.

## Demo, step by step

### 0. Once

```sh
pnpm install
```

Receiving addresses in `~/.haas/.env`:

```sh
X402_PAY_TO=addr_test1...            # any preprod address you control
X402_SOLANA_PAY_TO=<base58 wallet>   # any devnet wallet; create its USDC account once (step 2)
```

### 1. Pay on Cardano (USDM)

1. Payer wallet: a preprod mnemonic holding a few tADA (fees and min-UTxO,
   https://docs.cardano.org/cardano-testnets/tools/faucet/) and at least 0.5 USDM (Masumi's).
2. In `~/.haas/.env`: `X402_CLIENT_MNEMONIC="word1 … word24"` and `BLOCKFROST_PROJECT_ID=preprod…`.
3. `pnpm start` (the server), then in another terminal:

   ```sh
   pnpm spike:x402 cardano "Design a logo for a small coffee roaster"
   ```

   Expected: the 402 lists both chains, then `HTTP 202 after ~20-60 s`,
   `settlement: success=true tx=<64 hex>`, a `https://preprod.cardanoscan.io/transaction/…` link,
   and the job status with `settlement.explorerUrl`.

To fall back to tADA pricing (no USDM in the wallet): `X402_ASSET=ADA`.

If the hosted facilitator is down, start the self-hosted one (`infra/x402-facilitator/README.md`);
HAAS uses it automatically on the next start. To force it: `X402_FACILITATOR_URL=http://localhost:4022`.

### 2. Pay on Solana devnet (USDC)

1. Payer key: any devnet keypair, e.g. `solana-keygen new -o payer.json`, then its base58 secret
   (`node -e "console.log(require('bs58').default.encode(Buffer.from(require('./payer.json'))))"`).
   It needs **no SOL**: the facilitator is the fee payer.
2. Devnet USDC to the payer from https://faucet.circle.com (network: Solana Devnet).
3. The receiving wallet `X402_SOLANA_PAY_TO` must already have a USDC token account: send it any
   amount of devnet USDC once (the faucet works), or `spl-token create-account 4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU --owner <wallet> -ud`.
4. In `~/.haas/.env`: `X402_SOLANA_CLIENT_SECRET=<base58>`.
5. With the server running:

   ```sh
   pnpm spike:x402 solana "Design a logo for a small coffee roaster"
   ```

   Expected: `HTTP 202` within a few seconds, `settlement: success=true tx=<signature>`, a
   `https://explorer.solana.com/tx/…?cluster=devnet` link and the job status.

### 3. Switch chains on stage

Edit one line and restart: `X402_NETWORK=solana:devnet` (or `cardano:preprod`). Nothing else
changes; the client sees the new chain in the next 402.

## What happens on a paid request

1. Unpaid `POST /x402/route` with a brief: the brief is validated (400 if bad, before any payment),
   then 402 with a `PAYMENT-REQUIRED` header listing one `exact` option per offered network.
2. The client signs a transfer on one chain and retries with `PAYMENT-SIGNATURE`.
3. HAAS asks the facilitator for that network to `/verify`, then runs the handler: the brief is
   stored in the Store (`x402:pending:<job id>`) and the `202 {job_id, status_url}` is held back.
4. The facilitator `/settle`s: on Cardano it broadcasts the client's tx and waits until it is in a
   block; on Solana it co-signs as fee payer and submits. Only then is the 202 released.
5. The after-settle hook starts the job, once: the job id comes from the payment itself (Cardano
   tx hash, or a hash of the client-signed Solana tx), so retries of the same payment, and
   requests after a restart, land on the same job. The settlement (network, asset, amount, tx,
   explorer link, payer) is stored on the job and copied into the job result when it completes.
6. `GET /x402/jobs/<id>` (unpaid) shows `awaiting_payment` while settlement is in flight, then the
   job with its `settlement`, shortlist at the check-in, and result.

## Limits

- The 402 is built from the facilitators' `/supported`, fetched at the first paid-route call. If
  no facilitator for an offered network answers, that call fails with an error; drop the network
  from `X402_NETWORK` or point it to a working facilitator.
- x402.org serves testnets only. Solana mainnet needs a mainnet facilitator; the Coinbase CDP one
  requires API-key auth headers, which HAAS does not send yet.
- A paid request whose settlement succeeds while HAAS is down between verify and settle (a crash
  mid-request) keeps its brief in the Store, and the same payment retried starts the job; HAAS
  does not scan the chain for such payments on its own.
- Live status of the hosted facilitators was not checked from the build environment (its network
  policy blocks them). The Cardano Foundation lists both URLs on developers.cardano.org/x402.
